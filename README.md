# School Bus Tracking System – HTTP Relay

A lightweight FastAPI HTTP relay that enables ESP32 + SIM800L devices to communicate with the School Bus Tracking System backend.

The SIM800L communicates with the relay using HTTP. The relay forwards device requests to the FastAPI backend through its Cloudflare HTTPS URL.

This architecture is used because the SIM800L can have compatibility issues with modern HTTPS/TLS connections.

## Related Repositories

- [Backend – FastAPI](https://github.com/patilamar184/bus-tracking-system-backend)
- [Frontend – React Dashboard](https://github.com/patilamar184/bus-tracking-system-frontend)

## Technology Stack

- Python 3.10+
- FastAPI
- Uvicorn
- HTTPX
- python-dotenv
- ngrok
- Cloudflare Tunnel

## 1. Communication Architecture

```text
ESP32 + SIM800L
       |
       | HTTP
       v
ngrok Public HTTP URL
       |
       v
Local HTTP Relay :8080
       |
       | HTTPS
       v
Cloudflare Quick Tunnel
       |
       v
FastAPI Backend :8000
       |
       v
SQLite Database
```

The React frontend communicates directly with the backend through the Cloudflare HTTPS URL.

## 2. Prerequisites

Install the following:

- Git
- Python 3.10 or newer
- ngrok
- Cloudflare Tunnel (`cloudflared`)

Verify:

```bash
git --version
python --version
ngrok version
cloudflared --version
```

### Install ngrok

Create an ngrok account:

https://ngrok.com/

Install ngrok on Windows using the official instructions:

https://ngrok.com/download/windows

Configure your ngrok authentication token:

```bash
ngrok config add-authtoken YOUR_NGROK_AUTHTOKEN
```

Replace the placeholder with your personal ngrok authtoken.

### Install Cloudflare Tunnel

Download `cloudflared` for Windows:

https://developers.cloudflare.com/tunnel/downloads/

Verify:

```bash
cloudflared --version
```

For this project, we use a Cloudflare Quick Tunnel. It does not require a configured custom domain or a named tunnel.

## 3. Clone the Repository

```bash
git clone https://github.com/patilamar184/bus-tracking-http-relay.git

cd bus-tracking-http-relay
```

## 4. Create a Python Virtual Environment

```bash
python -m venv .venv
```

Activate:

**Windows CMD:**

```cmd
.venv\Scripts\activate
```

**Windows PowerShell:**

```powershell
.\.venv\Scripts\Activate.ps1
```

## 5. Install Dependencies

```bash
python -m pip install --upgrade pip
pip install -r requirements.txt
```

## 6. Configure Environment Variables

Create `.env` from `.env.example`.

**Windows CMD:**

```cmd
copy .env.example .env
```

**PowerShell:**

```powershell
Copy-Item .env.example .env
```

Open `.env` and configure:

```env
BACKEND_URL=https://YOUR-CLOUDFLARE-URL.trycloudflare.com
```

Replace the example URL with the actual Cloudflare URL generated by your backend tunnel.

Do not add `/api` at the end.

Example:

```env
BACKEND_URL=https://example-name.trycloudflare.com
```

The relay reads this value using `python-dotenv`.

## 7. Start the Backend

Before starting the relay, start the backend repository:

https://github.com/patilamar184/bus-tracking-system-backend

Run FastAPI:

```bash
uvicorn app.main:app --reload --host 0.0.0.0 --port 8000
```

## 8. Start Cloudflare Quick Tunnel

Open another terminal.

Run:

```bash
cloudflared tunnel --url http://localhost:8000
```

Cloudflare will generate a public HTTPS URL similar to:

```text
https://example-name.trycloudflare.com
```

Copy the URL and update the relay `.env`:

```env
BACKEND_URL=https://example-name.trycloudflare.com
```

If you change the `.env` file while the relay is running, restart the relay.

Keep the Cloudflare terminal running.

**Important:** The Quick Tunnel URL can change when the tunnel is restarted. Update `BACKEND_URL` whenever this happens.

## 9. Start the HTTP Relay

Open another terminal inside the relay repository.

Activate the virtual environment if necessary and run:

```bash
uvicorn relay:app --host 0.0.0.0 --port 8080
```

The relay is now available locally at:

```text
http://localhost:8080
```

Test it:

```bash
curl.exe http://localhost:8080/
```

Expected response:

```json
{
  "status": "Relay server running"
}
```

## 10. Start ngrok

Keep the relay running.

Open another terminal and execute:

```bash
ngrok http 8080
```

ngrok will provide a public endpoint.

Use the HTTP URL for the SIM800L firmware, for example:

```text
http://example.ngrok-free.dev
```

The exact URL depends on your ngrok account and endpoint configuration.

Keep the ngrok terminal running.

**Important:** If the ngrok endpoint changes, update the URL in the ESP32 firmware and upload the firmware again.

## 11. Device API Communication

The relay supports these endpoints:

| Method | Relay endpoint | Backend endpoint |
|---|---|---|
| POST | `/api/device/heartbeat` | `/api/device/heartbeat` |
| POST | `/api/device/location` | `/api/device/location` |

The relay forwards:

- JSON request body
- `Content-Type`
- `X-API-Key` authentication header

### Heartbeat Request

```json
{
  "device_id": "BUS-2"
}
```

### GPS Location Request

```json
{
  "device_id": "BUS-2",
  "latitude": 16.8524,
  "longitude": 74.5815,
  "speed_kmph": 25.4,
  "altitude_m": 560.2,
  "satellites": 8
}
```

The `device_id` and `X-API-Key` must match a device registered in the backend.

## 12. Test the Heartbeat Endpoint

Use Windows CMD:

```cmd
curl.exe -X POST "http://localhost:8080/api/device/heartbeat" -H "Content-Type: application/json" -H "X-API-Key: YOUR_DEVICE_API_KEY" -d "{\"device_id\":\"BUS-2\"}"
```

Expected response:

```json
{
  "message": "Heartbeat received",
  "device_status": "online"
}
```

## 13. Test the GPS Location Endpoint

```cmd
curl.exe -X POST "http://localhost:8080/api/device/location" -H "Content-Type: application/json" -H "X-API-Key: YOUR_DEVICE_API_KEY" -d "{\"device_id\":\"BUS-2\",\"latitude\":16.8524,\"longitude\":74.5815,\"speed_kmph\":25.4,\"altitude_m\":560.2,\"satellites\":8}"
```

Expected response:


Replace the example device ID and API key with your actual registered device credentials.

## 14. ESP32 Firmware Configuration

The ESP32 firmware should use the public ngrok HTTP URL, not the Cloudflare HTTPS URL.

Example:

```cpp
const char RELAY_URL[] =
  "http://example.ngrok-free.dev";

const char DEVICE_ID[] = "BUS-2";

const char API_KEY[] =
  "YOUR_DEVICE_API_KEY";
```

The firmware sends heartbeat and GPS location requests through the relay.

## 16. Troubleshooting

**Relay server not starting**
- Check that the virtual environment is activated.
- Install dependencies using `pip install -r requirements.txt`.
- Verify that `.env` exists and contains `BACKEND_URL`.

**Backend connection failed**
- Confirm FastAPI is running on port 8000.
- Check that the Cloudflare tunnel is active.
- Verify the `BACKEND_URL` in `.env`.

**ngrok connection failed**
- Check your ngrok authentication token.
- Confirm the relay is running on port 8080.
- Verify that the ngrok endpoint forwards to port 8080.

**401 Unauthorized**
- Check the device ID and API key.
- Make sure the API key belongs to an active device registered in the backend.

**502 Backend connection failed**
- Check the Cloudflare URL.
- Restart the relay after updating `.env`.

## 17. Security Notes

- Never upload `.env` files or API keys to GitHub.
- Keep `.env` in `.gitignore`.
- Rotate any API keys that have been exposed.
- The SIM800L-to-ngrok HTTP connection is unencrypted. The device API key can be exposed on this connection.
- This relay architecture is intended for development and prototype testing. Use an appropriately secured communication method before production deployment.
